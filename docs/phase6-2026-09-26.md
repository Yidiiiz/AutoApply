Scope is Phase 6 only. Existing Phase 2–5 changes are preserved. Validation uses the Phase 5
offline plugin, disposable profiles/databases, and local/intercepted fixtures.
No employer site, production account, live submission, or private history is
used. Production auto-submit configuration is not changed.

## 2. Snapshot/evidence model

`inspection.py` adds immutable `FormSnapshot` metadata, serialized as JSON, with
independent `Question` copies for readers. The adapter retains frame plus locator
tokens; it does not retain ElementHandles. Each lookup observes the current
document identity, URL, frame identities, DOM revision, control identities,
visibility, required/disabled state, current value/selection/validity, upload
revision, and browser security/dialog observations. Password/challenge values
are excluded from this observation. Protected-provider frames are not entered.

Browser-side WeakMaps identify controls and MutationObservers cover document and
discovered open shadow roots. Instrumentation marker attributes are ignored.
Navigation, frame attachment/navigation, control replacement, label/option/DOM
mutation, conditional fields, visibility/required changes, upload events, and
security/dialog evidence invalidate reuse. Expected value-only changes produce a
new immutable state snapshot while retaining unchanged field metadata. Structural
changes require full inventory. An inventory that itself mutates semantic options
is not cached as if the original generation remained unchanged.

This is deliberately conservative: unrelated DOM attribute changes can also
invalidate metadata. Every lookup still performs a small bulk generation read;
the saving is repeated full label/option/mapping discovery. It is not a cached DOM
tree, a mutation authorization, or a substitute for final validation.

`security.py` adds immutable `PageInspection` and `SubmissionResult`. A fresh
security observation at an Engine boundary can feed the security gate, page
condition, and submission classification through pure readers. Evidence is not
carried across interactions to authorize later mutations. Security remains fresh
after navigation, at control mutation, during upload observation, after Next,
before final action, and during post-submit observation. Adapter validation stays
fresh. Pre-submit skips only the redundant main-document normalized validation
inside the security snapshot because the adapter immediately performs that scan;
embedded-frame validation remains in the detector because adapter frame policies
differ. Post-submit retains its original validity inspection.

No cached snapshot authorizes a missing control, unknown answer, upload success,
or submission. Phase 5 descriptors, deterministic resolution, abstention,
candidate preflight, and signature/provenance persistence remain authoritative.

The shared Next operation takes one absolute budget, observes a stable current
signature, resolves the current action, clicks once, then waits for a stable
changed signature. Generic signatures now include document URL, heading, and
control identity/type/name; SmartRecruiters keeps its specialized signature and
attachment transition hook. Delivery is marked ambiguous before the click await.
A timeout after possible delivery produces `STEP_TRANSITION_UNCONFIRMED`, never
a second click. Security is inspected after the stable transition and prior
inventory/controls are invalidated.

Cursor changes follow the measurement: target-path geometry already returns the
main viewport, so movement reuses that same fresh payload instead of requesting
the viewport again at every point. Geometry and hit-testing remain fresh,
including ancestor frames, rerenders and final action checks. Geometry sampling
passes only the remaining geometry budget to nested bounding-box waits.

Remaining browser-path sleeps were audited:

| Location | Reason retained or replacement |
| --- | --- |
| Combobox, 20 ms | Bounded selected-value/menu polling: script property writes need not produce DOM mutations. Uses the shared operation deadline. |
| Cursor geometry sampling | Configured interval measures stability between distinct observations; nested waits use remaining budget. |
| Cursor movement schedule | Existing deterministic path timing; no new randomness or evasion. |

Unrelated service, worker/Discord, provider and filesystem retry polling is
unchanged. No randomized timing, fingerprint, proxy or anti-detection work was added.

## 4. Dropdown/combobox

`Deadline` stores an absolute monotonic end time. One outer `asyncio.timeout`
covers resolution, open/focus, optional typing, option appearance, exact match,
one option click, and commitment verification. Nested waits get remaining time;
diagnostics cannot start another full wait after exhaustion. Transition and upload
work use the same absolute-budget principle without reducing configured maxima.

Generic semantic options remain necessary for Phase 5 field signatures and
school/city resolution. Those cases still inspect live options during inventory,
with fresh security and a bounded discovery budget. An already visible menu is
not toggled; a search is performed only when the visible options cannot resolve
the intended value. The owned menu can remain open for the subsequent fill,
avoiding close/reopen work. Saved answers can supply search text, not option facts.

Before mutation, native and available custom options are compared against known
inventory signatures; a changed set holds instead of blindly applying stale
options. Locators are resolved again. Search-only controls that open on input,
asynchronous results, hidden duplicates, retained empty listboxes, rerendering,
and exact selected-value readback retain the Phase 2 commitment behavior. An
actually open uncommitted menu still fails. There is one intended selection click.

## 5. Upload lifecycle

Upload selection/request/status/metadata/completion/failure events advance an
`UploadTracker` revision and clear its accepted receipt. A successful stable
observation records a receipt keyed by URL, tracker revision, control keys,
document-scoped control identities, attachment DOM revisions, expected file
name/size, carried-evidence source, and current UI verdict.

Each subsequent readiness check still freshly observes security, attachment UI,
network state, busy/disabled/warning state and the current receipt key. An exact
accepted match avoids restarting the half-second stability window. Replacement,
removal, transient busy/removal mutations, late network failure, warning or an
incompatible step/navigation invalidates reuse. A changed acceptable state must
stabilize again; an expired budget or unknown state returns false.

The selection and readiness phases share the selection deadline. Greenhouse keeps
its filename/removal UI plus S3 evidence; Ashby keeps metadata-write completion and
accepted UI; SmartRecruiters keeps its visible accepted file entry and
same-session step receipt. `SessionAttachment` tracks main-frame navigation and
permits carry only through the observed transition in the same page/session.
Receipts are never restored from the database into another browser.

Generic behavior is preserved: native selected-file identity alone is not the
complete verdict. Stable current UI, fresh security, no pending/failed tracked
request, and no busy/disabled/warning state are also required. This generic policy
does not claim that an unobserved remote server accepted the file; ATS-specific
stronger evidence remains mandatory where supported.

`FileSnapshot` reuses the local resume hash/PDF header only when resolved path,
device/inode, size, mtime and ctime match. A read is checked against file identity
again afterward. A changed version invalidates the snapshot. The existing final
fresh byte-read/hash comparison before submission remains unchanged.

## 6. Page ownership

Every newly created dedicated-context application page/pop-up receives a
`PageLease`. New-page creation is serialized. Failed setup or cancellation releases
the lease; release cancels cursor input and closes the page in a `finally` block.
Intentional manual/security/unsupported/input holds retain their explicit owner.
Engine cleanup runs even when history export, telemetry or checkpoint handling
fails. Browser shutdown attempts context closure even after cursor failure, then
stops Playwright and clears ownership even if context closure raises.

Direct `Engine(fill_only=True)` enforces the one-page limit centrally, including
when its Browser context was already started. Only unowned blank startup pages in
the dedicated context are removed. A restored form is counted, not silently
closed. Unexpected pop-ups are owned and closed; a latched
`BATCH_TAB_LIMIT_VIOLATION` prevents proceeding even after their close. Pending
close tasks are drained during shutdown. Foreign-context pages cannot acquire a
lease. No personal browser/context is inspected or closed.

The dedicated final Submit physical-click implementation and the ordering
`probe arm -> durable transaction/intent -> observation reset -> one physical
click -> observation` are unchanged. Fill-only never enters that path. The source
comparison results are in `phase6-2026-09-26/submit-integrity.json`.
